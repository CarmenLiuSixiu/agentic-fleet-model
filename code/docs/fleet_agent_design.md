# 车队智能体(网约车/Robotaxi)接入设计 v0.1 (2026-10-25)

## 1. 要回答的问题
走廊上有一部分车属于一个网约车车队(Waymo 类), 车队调度系统本身是一个智能体。
- **Q1 份额门槛**: 车队份额多大时, 基础设施智能体与车队协调才有可测收益? (对标 Toso et al. 的"份额门槛"理论结果)
- **Q2 空车是关键筹码**: 车队约 41% 的里程是空驶(Waymo 2026Q2 全州: 巡游 26% + 去接驾 15%)。空车改道或延后出发不需要乘客同意, 成本远低于载客车。和空车谈, 能拿到协调收益的多大比例、花多少钱?
- **Q3 模型错了谁兜底**: 基础设施的世界模型结构错误时(METANET 压力测试), 能拒绝报价的车队能不能像 L3 协商车那样限制损失?

## 2. 和已有工作的关系
| 工作 | 做了什么 | 没做什么(我们补) |

| CoopRide (Wang, Hao, ..., Yong Li, KDD 2025) | 全城网格多智能体 RL 派单, GNN 学网格间协作强度, 三城真实订单 | 行程时间外生, 不考虑车队流量造成的拥堵; 没有基础设施方 |

| Toso, Parise, Frasca, Kibangou (arXiv 2024/25) | 车队运营方与自私个体的博弈, 车队份额对无政府代价的影响, 存在份额门槛 | 静态交通分配, 无动态拥堵、无基础设施智能体 |

| 本项目 v4 / 2026-04 | 检测器标定的双类 CTM 世界模型 + 基础设施 MPC + 车辆能动性阶梯 L0–L4 | 车队作为整体智能体 |

一句话定位: **派单文献把交通当背景, 交通控制文献把车当被动流量; 我们让基础设施智能体和车队智能体在同一个标定过的动态世界模型里谈判。**

## 3. 模型
### 3.1 车辆类别(CTM 商品)
现在 4 类: 过境人驾 O_H、过境智能车 O_A、本地人驾 L_H、本地智能车 L_A。
新增 2 类过境车队车: **F_occ(载客)**、**F_emp(空驶)**。本地车不分车队(车队行程以过境为主; 先简化)。
- 车队份额 s_F 占过境需求的比例, 情景扫描 {0, 1, 5, 10, 30}%; 空驶比例 e = 0.41(全州实测), 敏感性 {0.2, 0.6}。
- 私家智能车份额 s_A 默认 0, 与车队分开研究; 2×2 时再打开。
- 实现: ctm.py 的 K 和类别标志(IS_A / IS_LOCAL)改成按类配置的向量, s_F = 0 时必须逐位复现现有结果(过关测试)。

### 3.2 车队智能体
- 目标: 最小化车队成本 = 载客车乘客时间 × VOT(对数正态, 均值 $25/h) + 空驶车时间 × 运营成本 c_E(默认 $20/h, 敏感性 10/40) − 收到的激励。
- 自己的信息: 实时路线行程时间(和 L1 一样看到真实路况)。车队不知道基础设施的模型。
- 动作(每 5 分钟):
  1. 载客车与空车各自的路线分配(A/B 比例);
  2. **空车出发延后**: 把一部分空车在起点"暂存"5–15 分钟再出发(相当于延后再平衡), 暂存有成本(c_E × 时间 + 接下一单变晚的惩罚)。
- 行为档(对应私家车阶梯):
  - F0 车队不受协调, 按自身成本选路(=车队版自私, 但车队内部协调, 是 Toso 的"协调车队");
  - F1 服从: 完全按基础设施要求分配;
  - F2 谈判: 基础设施给车队一个报价(每改道一辆 $x、每暂存一辆 $y), 车队按自身成本最优回应, 可以只接受一部分、可以全拒;
  - F3 谈判 + 只对空车开放: 载客车不动, 只交易空车(Q2 的核心对照)。

### 3.3 基础设施智能体
不变: 世界模型 MPC(或只看检测器的 MHE + MPC), 控制 6 个匝道计量 + 对车队的报价 (x, y)。
报价由 MPC 在候选报价中搜索, 车队回应用基础设施"相信的"车队成本模型预测(可以错: c_E、VOT 误设)。

### 3.4 真值世界
和现在一样: CTM 真值(标定 + 需求噪声 + 容量下降 + 事故)与 METANET 压力测试两套。
世界模型参数用 v4(2017)先跑通; 2026 逐日标定完成后换成 2026 参数。

## 4. 实验(预注册读法)
| 编号 | 设计 | 读法 |
| --- | --- | --- |
| F1 份额门槛 | s_F × {F0, F1, F2, F3}, CTM 真值, 10 天配对 | 找最小 s_F 使 F2 的 TTS 降幅 90% 区间不含 0; 若 30% 仍不显著, 照实报"无门槛内收益" |
| F2 空车筹码 | F3 vs F2 | F3 拿到 F2 收益的比例与每车·时成本; 若 ≥ 70% 收益且成本 ≤ 一半, 结论为"空车是主筹码" |
| F3 暂存杠杆 | F2 有/无暂存动作 | 暂存单独贡献; 报告空驶时间增加(M-VMT 视角, Yu)与车队成本 |
| F4 模型错误 | METANET 真值下 F1 vs F2 | F2 损失是否 < F1 损失(复现 L3 的兜底机制); 若不是, 照实报 |
| F5 只看检测器 | MHE 运营方 | 保住 oracle 收益的比例 |
指标: 总行程时间 TTS、车队成本、乘客延误、空驶车·时、激励花费与每节省车·时成本、最差匝道等待(公平)、车队份额与 Toso 门槛的对照。

## 6. 实现顺序
1. ctm.py 类别向量化 + 过关测试(s_F = 0 逐位复现 v4 闭环; 6 类守恒)。
2. fleet.py: 车队成本、最优回应、暂存队列(起点处的空车等待队列)。
3. agentic.py: World / MPC 加车队报价维度。
4. run_fleet.py: F1–F5, 并行跑。
5. RESULTS.md 新节 + 图(份额-收益曲线)。
